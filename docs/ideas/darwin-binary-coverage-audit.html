What the server doesn't run yet

Every capability resolves a bare name — "ls", "osascript" — through policy.ResolveBinary, which only ever looks inside four trusted directories. This is a census of everything that lives in those directories, split against what the engine actually invokes today.

Hand-picked from the 1,200 for fit with the capability-engine model: a well-scoped CLI surface, a clear read vs. mutate story, and a use case the roadmap already gestures at (power, media, storage, deeper diagnostics). Badge = how much guardrail work it would need before shipping.

Deliberately left out

These showed up in the same directories and could technically be resolved, but the shape of the tool argues against ever wrapping them — matches the project's existing stance of dropping destructive, low-value-add operations rather than adding a guardrail for everything.
