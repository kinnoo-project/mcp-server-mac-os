(internal/engine/mutate_maps.go) The free-text length check used `len(v)`
(bytes) while the error message said "characters" and the constant is documented
as a character cap. Non-ASCII input would be rejected early and the reported
length would be wrong.

**fixed**
Switched the check to `utf8.RuneCountInString(v)` and reported that count in the
error. This is a real behavioural bug rather than a cosmetic mismatch: place
names are routinely non-ASCII, and at three bytes per rune a byte cap rejected
an ordinary address at about 85 characters against an advertised limit of 256 —
so "東京駅" style destinations and accented European addresses could fail
validation for no reason a user could see. Updated the constant's doc comment to
say the cap is measured in runes, and added
`TestValidateMapsText_CapsCharactersNotBytes`, which asserts a 256-character
all-multibyte address is accepted (with a premise check that it does exceed 256
*bytes*, so the test cannot silently stop testing anything), that one character
over is still rejected, and that the message reports the character count.
`docs/TESTS.md` notes the byte-vs-character distinction in the Maps subsection.
