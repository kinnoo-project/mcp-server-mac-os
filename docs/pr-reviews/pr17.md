# PR #17 review — Mvp2/impl13 (process & resource monitoring)

2026-06-21, mode: fix

(internal/engine/mutate_process.go) `terminate_process` is documented (and
described in comments) as a safe stop for background/daemon processes, but
`stageTerminateProcess` allowed sending SIGTERM to *any* PID, including GUI
apps. That bypasses the normal Quit Apple Event / save prompts and contradicts
the safety contract that GUI apps should go through `quit_process`. (Copilot)

**fixed**
`stageTerminateProcess` now resolves the PID's executable path and, when it
belongs to a `.app` bundle (`appNameFromExePath` returns non-empty), refuses with
an error directing the caller to `quit_process`. This is the mirror image of
`stageQuitProcess` refusing a non-app PID, so the two mutators cleanly partition
the process space: GUI apps quit gracefully (and can prompt to save), everything
else gets SIGTERM. Updated the manifest summary (`process.json`), the function
doc comment, and the design note (`docs/issues/note-process-monitoring-design.md`).
Added `TestMutateProcess_PartitionByAppBundle`, which locks the shared
`appNameFromExePath` discriminator both mutators branch on (a `.app` path must be
classified as a GUI app; a plain binary must not), so a future change that broke
the partition would surface in tests. Fixed in 3606aa9.
