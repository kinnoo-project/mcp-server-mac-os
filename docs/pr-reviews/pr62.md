## Comments and resolutions

### 1. `runQuarantineInfo` misreports non-"absent" failures as "not quarantined" (builtins_security.go:208) — FIXED
Copilot noted that treating *any* non-zero `xattr -p` exit (or empty stdout) as
"NOT quarantined" is correct for the common `No such xattr` (attribute absent)
case but would also swallow *other* failures — a permission error, an unexpected
xattr error, a file that vanished after validation — reporting them as
"not quarantined". For a security/trust decision that is the dangerous direction:
a failed read could hide a real download flag.

Fix: extracted the branching into a pure `interpretQuarantineResult(path, res)`
that distinguishes three cases instead of two:
- **present** (exit 0 with a value) → decode via `renderQuarantine`;
- **absent** (`No such xattr` in stderr, or a clean exit-0 empty value) → the
  benign "NOT quarantined" verdict;
- **any other failure** → returns an *error* carrying xattr's stderr, never a
  false "not quarantined".

Confirmed against the real `/usr/bin/xattr`: an unset attribute exits 1 with
`xattr: <path>: No such xattr: com.apple.quarantine` on stderr, which the new
marker check keys off. Covered by `TestInterpretQuarantineResult` (present /
absent / permission-error branches).
