Copilot review of PR #41 (branch `feat/system-notify-speak` → `build`).
State: **COMMENTED**, 4 inline comments — all four were the same underlying

## The finding (accepted)

Copilot noticed that the auto-commit execution path already appends a fixed
suffix for a nil-inverse operation:

```go
// internal/server/tools.go:227 (autoCommitMutation)
return textResult(fmt.Sprintf("%s\n\nDone: %s. This cannot be undone.", describe, c.Name))
```

Since `describe` includes the mutator's staged `Preview`, and my previews ended
with "… This cannot be undone (…)", the final tool output would read
redundantly, e.g.:

> Post a macOS notification titled "Backup": "Export finished". This cannot be
> undone (a notification, once shown, cannot be recalled).
>
> Done: notify. This cannot be undone.

Verified valid: `open_settings` (the existing irreversible auto_commit op)
deliberately omits the phrase from its preview for exactly this reason — I had
not followed that precedent.

## The fix (commit `6692694`)

Rephrase both previews to keep the irreversibility **reason** but drop the
duplicated phrase:

- `notify` → "… A shown notification cannot be recalled."
- `speak`  → "… Audio plays immediately."

Updated the two preview assertions to (a) check for the reason and (b) assert
the phrase "cannot be undone" is **absent**, so a future regression that
re-introduces the duplicated suffix fails the test. Added a short rationale to
`docs/issues/note-notify-speak-design.md`.

No behavioral change to command construction, injection hardening, caps, or the
nil-inverse/auto_commit classification — this was purely the human-facing
preview text.
