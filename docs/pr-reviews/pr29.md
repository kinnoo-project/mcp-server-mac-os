# PR #29 review — Photos app capabilities

2026-06-22, mode: fix

Addressed three Copilot review comments (all agreed with). Fix commit: `2bb06fc`.

---

(README.md) The intro example "Turn on Bluetooth" suggests the server can toggle
Bluetooth directly, but the system domain documents that toggling Bluetooth isn't
supported and should be handled via `open_settings` (pane `bluetooth`).

**fixed**
Changed the intro example to "Open my Bluetooth settings.", which reflects the real
capability (opening the Bluetooth Settings pane) rather than implying a toggle the
server doesn't support.

---

(README.md) The Photos example "Tag these with 'vacation'" reads like an additive,
batch tag operation, but `set_keywords` replaces the entire keyword list for a
single item id.

**fixed**
Reworded to "Set this photo's keywords to 'vacation, beach'." with a "(replaces that
photo's keyword list)" note, so it matches the single-item, replace-not-append
behavior and no longer implies a batch/additive tag.

---

(internal/engine/mutate_photos_weak.go) `import_photos` accepts any non-directory
path that `os.Stat` resolves, including special files (devices, sockets, etc.).
Tighten to require `Mode().IsRegular()`.

**fixed**
The stage-time check now refuses a path unless `info.Mode().IsRegular()` is true, so
directories AND special files (devices/sockets/fifos) fail fast — consistent with
how `send_message` validates attachments. Added a directory-rejection assertion to
`TestStageImportPhotos_ExistingFiles`.
