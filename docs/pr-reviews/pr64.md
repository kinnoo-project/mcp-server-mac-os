# PR #64 — V7 storage domain (Time Machine, volumes & disk images)

Copilot reviewed 15/15 changed files and left **3 inline comments** (no blocking
verdict — one real correctness gap plus its test-coverage twin, and one
docs/behavior-drift nit). All three addressed in the follow-up commit `c673771`
on the PR branch.

## Comments and resolutions

### 1. `validateVolumeIdentifier` accepts `/Volumes/.` and `/Volumes/..` (builtins_storage.go:84) — FIXED
Copilot noted that `volumeMountPattern` (`^/Volumes/[A-Za-z0-9 ._+()-]+$`)
includes `.` in its charset, so the single-component special paths `/Volumes/..`
and `/Volumes/.` matched the "single-component /Volumes path" allowlist and were
returned as valid identifiers. When normalized those resolve *outside* the
intended target — `/Volumes/..` → `/`, `/Volumes/.` → `/Volumes` — undermining
the stated single-component traversal defense for the diskutil/hdiutil operands.

This was a genuine gap (the earlier reject test only covered the multi-slash form
`/Volumes/../etc/passwd`, which the "no extra slash" rule already caught). Fix:
`validateVolumeIdentifier` now rejects the two pure dot-components explicitly,
*before* the pattern check, with a clear message. A name that merely *contains*
dots (e.g. `/Volumes/My.Disk`) is unaffected — only `.` and `..` as the whole
name traverse, so only those two are rejected.

### 2. Reject table missing the `/Volumes/.` and `/Volumes/..` cases (builtins_storage_test.go:71) — FIXED
The test-coverage twin of #1. Added both `/Volumes/.` and `/Volumes/..` as
explicit rows in `TestValidateVolumeIdentifier`'s reject table so the traversal
edge case cannot silently regress if the pattern or guard is later touched.

### 3. `mount_volume` manifest description narrower than the validator (storage.json:64) — FIXED
`mount_volume`'s `volume` param description said it accepts only "a disk
identifier", but `stageMountVolume` validates through the shared
`validateVolumeIdentifier`, which accepts a disk id **or** a single-component
`/Volumes` mount path. Copilot flagged the drift between the advertised and the
actual accepted shape. Fix: the description now states both forms (noting a disk
identifier is the usual choice for an attached-but-unmounted volume), matching
runtime behavior so clients and eval descriptions don't diverge from it.
