# PR #35 review — feat(engine): stdin-carrying staged commands + previewSnippet (U0)

2026-07-01, mode: fix (Copilot review)

(internal/engine/mutate.go) The `Stdin` doc comment claimed stdin bytes can
never be parsed as "script" — not generally true (sh/python execute their
stdin); stdin only guarantees the payload won't be parsed as argv flags/paths.

**fixed**
Comment narrowed to the argv-only guarantee and now states explicitly that a
mutator must pair `Stdin` with a data-sink utility (tee, pbcopy), never an
interpreter.

---

(internal/engine/mutate_test.go) `TestRunCommand_StdinIsPureData` claimed
"byte-for-byte" but asserted only `strings.Contains`, which would pass with
unexpected prefix/suffix bytes.

**fixed**
Assertion is now exact equality (`out != hostile`), and the docstring says so.

---

(internal/engine/mutate.go) `RunCommand` accepted arbitrarily large stdin
payloads; staged plans/inverses sit in the in-memory transaction stores until
consumed/TTL, so unbounded payloads are a memory-pressure/DoS vector.

**fixed**
Added `maxStdinBytes` (16 MiB, a test-lowerable var mirroring
`commandTimeout`) enforced at the `RunCommand` choke point before any
subprocess runs; mutators keep their own tighter caps on top. Regression test
`TestRunCommand_StdinSizeCap`.

---

(docs/issues/note-engine-stdin-commands.md) Same over-broad "never parsed as
script" claim in the design note.

**fixed**
Note now limits the claim to argv parsing, calls out that safety depends on
the chosen target utility, and documents the new size cap.
