# PR #53 review — build -> main - added 18 new capabilities

2026-07-03, mode: fix (Copilot comments) + independent full-diff review (sub-agent, U0–U17)

This PR merges the 18 feature units U0–U17 (~11.6k insertions, 115 files) from
`build` into `main`. Beyond addressing Copilot's two comments, an independent
review agent audited the entire diff for bugs, cross-unit inconsistencies,
security flaws (injection surfaces in particular), PII/credential leaks, and
stale documentation. Verdict: **no critical or high findings**; 4 medium and 7
low findings, all triaged below. The reviewer confirmed the osascript `--`
hardening is structural (one shared seam, unit-tested, registry-gated), every
AppleScript in the diff binds values via `on run argv` (zero script-source
interpolation), no shell wrappers exist anywhere, the two-phase stage→execute→
undo discipline is consistent (Trash-routed deletion throughout, no `rm` in the
diff), and an exhaustive sweep of email-like/phone-like strings found only
reserved placeholders — no real PII, tokens, or secrets.

Added `TestFormatSpotlightResults_CompactsOversizedOutput` (200 long paths must
come back trimmed with the truncation notice).

overstates what the item cap alone guarantees.

## Independent review findings (sub-agent)

(internal/engine/builtins_spotlight.go) **M1** — same defect as Copilot's first
comment, found independently: committed `spotlight_search` output is unbounded.

**fixed**
As above (compaction + regression test).

---

(internal/engine/injection_sweep_test.go) **M2** — the injection coverage gate
covered free-text *builtins* only; mutators assemble their own Forward/Inverse
commands too, but nothing structural forced the next free-text mutator to carry
a guard and a regression test.

**fixed**
Added `reviewedFreeTextMutators` (43 entries, each documenting the mutator's
guard and its test) and the mirror-image gate
`TestInjection_MutatorFreeTextParamsAreReviewed`. A future free-text mutator now
fails the build until it is reviewed. `docs/TESTS.md` updated to describe both
gates.

---

(internal/engine/mutate_filesystem.go) **M3** — `stageMkdir` baked the raw,
possibly relative path into both `mkdir` and the `rmdir` inverse, unlike every
other filesystem mutator (which resolve absolute precisely so undo is stable if
the server's working directory changes).

**fixed**
`stageMkdir` now resolves the path with `filepath.Abs` after the dash-guard.
Added `TestStageMkdir_ResolvesRelativePathAbsolute`.

---

(internal/engine/mutate_filesystem.go) **M4** — TOCTOU window: staging proves a
destination doesn't exist (`write_file`/`move`/`copy`), but execute replays the
staged command verbatim with no re-check, so a file created between stage and
confirm gets clobbered (recoverably — undo trashes it — but silently).

**status**: open — documented in
`docs/issues/issue-stage-execute-race-windows.md`. Deliberately NOT fixed with
`mv -n`/`cp -n`: BSD no-clobber flags exit 0 when they skip, so execute would
report success while doing nothing and the recorded inverse would then relocate
the wrong file. The right fix is an engine-level execute-time precondition
re-probe ("state changed since staging, re-stage"), a cross-cutting change
deferred rather than half-done here.

(internal/engine/builtins_mail_reads.go) **L4** — `read_message` accepted
all-digit ids of any length; a 25-digit id overflows AppleScript's `as integer`
inside the script and the failure was mapped to a misleading "grant Automation
access" hint.

**fixed**
Ids longer than 19 digits (past any real Mail id) are rejected up front with a
"use list_inbox" error. Added a regression case to
`TestReadMessage_RejectsBadID`.

---

(internal/engine/builtins_appstore.go) **L5** — `search_app_store` rendered
network-controlled listing text (name/seller/price) verbatim; a crafted listing
containing newlines could fabricate extra result lines (e.g. a bogus
"(App Store id N)" row) steering the model to open a different app.

**fixed**
Added `flattenControl` (control characters → spaces) applied to all
remote-controlled fields before rendering. Added
`TestRenderAppStoreResults_FlattensControlCharacters`; `docs/TESTS.md` updated.

---

(internal/engine/builtins_mail_reads.go) **L6** — a stale `read_message` id
triggers a fallback scan of every mailbox of every account, which can be slow
on large stores.

**fixed**
Accepted as bounded (the 2-minute engine kill caps it); the `read_message`
manifest summary now warns that a stale id can be slow, so the model prefers
re-listing.

---

(internal/engine/mutate_filesystem.go) **L7** — two plans staged before either
executes can compute the same collision-free `~/.Trash` name for the same
basename; the second executed `mv` lands inside or replaces the first.

**status**: open — same execute-time re-probe design as M4; documented with it
in `docs/issues/issue-stage-execute-race-windows.md`. Rare, low blast radius
(everything still lands in the Trash).
