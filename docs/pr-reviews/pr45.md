# PR #45 — feat(mail): read-only `list_inbox` + `read_message` (U10)

Base: `build` · Branch: `feat/mail-inbox-reads` · Copilot review: **COMMENTED** (1 inline)

## Summary

Adds two read-only Mail.app operations to the existing `application-mail` domain
(no new MCP tool): `list_inbox` (most recent N messages) and `read_message`
(one message's full body by id). Both drive Mail through the hardened
`runOsascript` seam. Also extracted a shared `osascriptArgv` helper so the read
path and the mutating path provably share the `--` terminator.

## Copilot review outcome

Copilot generated **1 inline comment** (plus the standard overview). No approval
gate blocked; the comment was a valid, actionable correctness/UX point.

### Comment 1 — `read_message` id not validated numeric (FIXED)

**File:** `internal/engine/builtins_mail_reads.go:173`

> `readMessageScript` coerces the incoming argv id to `as integer`, but
> `runReadMessage` passes the raw `id` string through after only an emptiness
> check. If the model/user supplies a non-numeric id (e.g. includes a prefix
> like "id: 123"), AppleScript will fail type coercion and the error will be
> wrapped as a generic Mail automation failure (with the System Settings hint),
> which is misleading for a caller error. Trim and validate that the id is
> numeric before invoking osascript so the failure is a clear, actionable input
> error.

**Assessment:** Correct. A message id is an integer that the script coerces with
`as integer`; a non-numeric id (a listing line copied verbatim as `"id: 123"`,
say) would trip that coercion and surface as the misleading "grant Automation
access in System Settings" hint rather than a plain caller error. The `--`
terminator already made the value *inert* (no injection risk), but the error
message was still misleading.

**Fix (`07ab0da`):** `runReadMessage` now trims the id and validates it is all
ASCII digits (reusing the existing `isAllDigits` helper) *before* invoking
osascript, returning `read_message: 'id' %q is not a numeric message id (use
list_inbox to get a current id)`. This is layered on top of the `--` terminator,
not a substitute for it. Expanded the guard test into `TestReadMessage_RejectsBadID`
covering missing / blank / non-numeric / dash-leading / hex ids. Updated the
`reviewedFreeTextBuiltins` note (`id validated numeric then passed as argv data
after '--'`) and the design doc.

Replied to the inline comment referencing `07ab0da`.
