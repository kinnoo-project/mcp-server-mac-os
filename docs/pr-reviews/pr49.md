## Comments and how each was addressed

All three were data-quality/consistency refinements, not correctness bugs in the
security-critical paths (the `--` terminator and marker-based inverse were already
correct and tested). Fixed in `97662b4`.

1. **`validateContactPhone` accepted zero-digit inputs** (`mutate_contacts.go`).
   The validator only rejected disallowed runes, so a "number" made entirely of
   separators (`()`, `--`) passed. Fixed by counting digits and enforcing the same
   **3–15 digit** range as `canonicalizePhoneNumber`; the error message now also
   lists dots (which the function already accepted). Added a `phone with no
   digits` rejection test.

2. **Email not checked for control characters** (`mutate_contacts.go`). The
   control-char sweep covered only `first_name`/`last_name`/`organization`, and
   `plausibleEmail`'s regex (`[^@\s'"]`) would let a NUL byte through — which then
   fails at osascript argv assembly and could corrupt the staging preview. Fixed
   by sweeping **every** free-text field (adding phone and email), switched to an
   ordered slice so the field named in the error is deterministic. Added a
   `control char in email` rejection test.

3. **Manifest phone description omitted dots / the digit range**
   (`contacts.json`). The description said "spaces/dashes/parentheses" while the
   validator also accepts `.`. Updated the description to state the 3–15 digit
   range and that dots are accepted, matching the validator.

## Why the core design needed no change

- **Injection.** Every model value crosses into AppleScript as `--`-terminated
  `on run argv` data; `TestGetContact_HostileNameLandsAsData` and
  `TestStageCreateContact_HostileFieldLandsAsData` prove flag-like values land as
  data. The field-shape validation the comments touched sits *on top of* that
  structural guarantee.
- **Undo safety.** `create_contact`'s inverse deletes by a unique crypto-random
  marker written to the new card's note field, so it can only ever remove the
  self-created contact (`TestStageCreateContact_MarkerIsUnique`).
- **No live address-book access in tests**, and the tool-surface count/list
  assertion (21 tools) was updated in the same PR.
