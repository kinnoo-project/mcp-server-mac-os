# PR #34 review — eval routing fixes + skill updates

2026-07-02, mode: fix

---

(internal/server/menu_test.go) `TestDomainDescription_ListsEveryOperationUpFront` uses
`strings.Contains(summary, op.Name)` to verify the "All operations:" list. This produces
false positives when one operation name is a substring of another — "move" is contained in
"remove", so a missing "move" entry would silently pass. The test was meant to catch
missing operations due to truncation, but substring matching defeats that purpose.

**fixed**
Replaced the `strings.Contains` loop with exact token parsing: extract the "All operations:"
line from the description, split on `", "`, build a `map[string]bool` of listed names, and
check `listedOps[op.Name]` by equality. A genuinely missing operation now fails the test.

**fixed**

(docs/issues/filesystem-batch-move-and-menu-truncation.md) The note claimed batch move via
`mv` has "no partial-completion state for undo to reason about." This is incorrect: `mv`
with multiple sources is NOT atomic — a permission error or cross-device move mid-batch
leaves some sources already moved and others not. The engine code itself (`mutate_filesystem.go`
lines 121–128) correctly documents this, so the issue note was out of sync.

**fixed**
Replaced the false claim with wording aligned to the engine code: the operation is NOT atomic,
`mv` can fail partway, and the inverse is re-runnable — it moves back exactly the files that
made it across, since the inverse targets the staged destination paths.
