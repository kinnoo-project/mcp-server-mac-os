# PR #31 review — batch move via source_glob + truncation-resilient tool menus + docs

2026-07-01, mode: fix

(internal/engine/mutate_filesystem.go) normalizeWhitespace's docstring says it
collapses whitespace to a single space, and suggestWhitespaceMatch relies on
"runs of whitespace" normalizing the same way, but the implementation mapped each
whitespace rune to a space without collapsing consecutive ones — so a tab vs.
multiple spaces (or any multi-rune run mismatch) wouldn't be detected.

**fixed**
normalizeWhitespace now tracks a prevSpace flag and emits a single ASCII space per
whole run of whitespace, matching its docstring and the contract
suggestWhitespaceMatch depends on. Added TestNormalizeWhitespace_CollapsesRuns
covering ordinary spaces, tabs, multi-space runs, mixed runs, U+202F, and
leading/trailing runs.

---

(internal/engine/mutate_filesystem.go) The stageMoveGlob comment claimed a single
mv invocation means "there is no partial-completion state." That overstates
atomicity: mv can fail after moving a subset of sources (permissions, cross-device
rename fallback), and the engine runs Forward as one command with no rollback on
failure — future maintainers shouldn't assume undo semantics are stronger than
they are.

**fixed**
Reworded the doc comment to state explicitly that the batch is NOT atomic and a
single mv can fail partway with no automatic rollback. Clarified that what the
single-command shape actually buys is a well-defined, re-runnable inverse (move
everything in destDir back to commonParent restores whatever moved), not
atomicity. The three correctness invariants are unchanged.

---

(internal/engine/mutate_filesystem_test.go) TestStageMoveGlob_Rejects claimed to
cover the shared-parent rejection, but the second temp dir (`other`) it created
never participated in any source_glob pattern, so the multi-parent guardrail was
never actually exercised.

**fixed**
Removed the unused `other` dir. The test now creates two sibling subdirs (d1, d2)
under a shared ancestor, each holding a file, and adds a "spans directories" case
globbing `span/*/*.png`. filepath.Glob (which has no brace syntax) expands the
intermediate wildcard to two matches under different parents, genuinely tripping
the shared-parent rejection. Verified out-of-band that the glob yields 2 matches
with 2 distinct parents.

**fixed**
Rewrote the note as complete sentences following the issue template, formatted the
