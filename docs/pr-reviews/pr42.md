# PR #42 review — feat(system): AirPlay discovery + keyboard input-source reads (U7)

2026-07-02, mode: fix

Copilot submitted a COMMENTED review with two inline comments, both on
`internal/engine/builtins_devices.go` and both real correctness issues in the
AirPlay browse. Addressed in commit `ab0c41c`.

---

(internal/engine/builtins_devices.go:73) `res == nil` was returned as an error,
but `runCommand`/`execCommand` only return a nil `res` when the context is
already done before the subprocess starts — a case the earlier `ctx.Err()` check
already handles. So the branch was effectively dead, and if it were ever reached,
treating an empty browse as a failure is wrong: finding zero AirPlay receivers is
a normal outcome (nothing powered on, or the Local Network prompt not yet
granted).

**fixed**
Removed the error branch. The code now guards `res == nil` defensively by
treating it as empty stdout and rendering the normal "no receivers found"
message (which `renderAirplayDevices` already produces for the empty case) rather
than erroring.

---

(internal/engine/builtins_devices.go:114) The browse parser tracked presence with
a single boolean per device *name* and cleared it on any `Rmv`. Because
`dns-sd -B` advertises the same receiver once per network interface, a `Rmv` on
one interface can arrive while the receiver is still present on another — the old
code would wrongly drop it. Separately, `order` insertion keyed off the `present`
map's key-existence, so a name whose first row in the window was a `Rmv`
(creating the key) followed by an `Add` would never be appended to `order` and
would be missing from results.

**fixed**
Presence is now tracked per `(interface, name)` — a `map[string]map[string]bool`
of the interface ids currently advertising each name — so a device stays listed
while at least one interface still advertises it, and a per-interface `Rmv` only
withdraws that interface. First-seen ordering moved to a separate `seen`/`order`
pair, decoupled from presence, so an initial `Rmv`-then-`Add` is retained. Added
two regression tests (`TestParseAirplayDevices_RemoveOneInterfaceKeepsDevice`,
`TestParseAirplayDevices_RemoveThenAdd`) and re-smoke-tested live (still de-dups
the two real receivers across interfaces).
