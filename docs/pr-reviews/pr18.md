(internal/engine/builtins_network.go) `validateNetworkHost` allowed `':'` in any
hostname, so `apple.com:443` (host:port) passed validation despite the
manifest/help text saying it must be a bare host — confusing ping/dig failures
and a slightly wider input surface. (Copilot)

**fixed**
There's no flag-injection escalation (`:` isn't an option char for ping/dig),
but host:port simply doesn't work — both tools treat the whole string as a
hostname and fail confusingly — and it contradicts the documented contract, so
tightening is correct (matches the user's "if it doesn't work, reject it"). A
`':'` is now permitted only when the value parses as an IP literal
(`net.ParseIP`), so IPv6 literals still pass while host:port is rejected up front
with a clear message. Added `apple.com:443` and `8.8.8.8:53` to the reject table
and `::1` to the accept table.

(internal/engine/builtins_notes.go) `list_notes`/`search_notes` fetch metadata
for *every* note and apply the limit in Go after parsing/sorting; because
`execCommand` buffers full stdout, a large Notes library can drive significant
CPU/memory before the Go cap kicks in. Suggested bounding AppleScript output or a
top-N strategy. (Copilot)

**fixed (search_notes) / explained (list_notes)**
`search_notes` was the genuinely expensive path: it reads each scanned note's
full `plaintext` to match, so cost scaled with total library size. It now takes
an optional `folder` parameter (mirroring `list_notes`) that confines the search
— and thus the per-note body reads — to one folder, the resource-conscious path
on a large store; the manifest guides the model to scope on big libraries. This
also realizes the user's intent ("scope the search rather than scan everything").
`list_notes` was left as-is by design: it reads only lightweight metadata
(id/title/date/folder, never bodies) and its returned text is already capped by
the shared output budget, so growth is bounded in practice; a true in-AppleScript
newest-first top-N for the all-folders case would require sorting AppleScript
can't do cheaply, making folder scoping the pragmatic bound. Fixed in 3833b5a.
