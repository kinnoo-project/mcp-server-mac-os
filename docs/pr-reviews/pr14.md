# PR #14 review — Mvp2/impl10

2026-06-20, mode: fix

Addressed three Copilot review comments on the `application-notes` capability.
All fixes landed in commit `fcf354c`; pipeline (`go build` / `go vet` / `gofmt`
/ `go test ./...`) green before push.

---

(internal/engine/builtins_notes.go) `read_note` trims all trailing newlines via
`strings.TrimRight(..., "\n")`. Since `osascript` appends exactly one trailing
newline, trimming all of them can drop user-authored content (a note that
intentionally ends in blank lines). Should trim exactly one, like
`probeNoteBody`.

**fixed**
Switched to `strings.TrimSuffix(res.Stdout, "\n")` so only the single
osascript-appended newline is removed; trailing blank lines in the note body now
round-trip. Comment updated to record the rationale and point at probeNoteBody.

---

(internal/engine/mutate_notes.go) `append_to_note` checks `text == ""` rather
than trimming, so whitespace-only input stages a no-op-ish append (an empty
block) with a misleading preview. Should reject after `strings.TrimSpace`, like
`send_message`.

**fixed**
Now rejects `strings.TrimSpace(text) == ""` with a "(non-whitespace)" hint.
Added `TestStageAppendToNote_Rejects` covering missing id, blank id, and
empty/whitespace text — all of which fail at validation before the live Notes
probe, so the test touches no real note.

---

(docs/issues/note-application-notes.md) The issue/note template ends with a bare
`**fixed**` marker with no explanation, which reads as incomplete; other
`docs/issues/` files omit the marker for unresolved items.

**fixed**
Removed the dangling `**fixed**` marker. The limitation it sat under
(cross-account folder targeting) is deferred/unresolved, so per CLAUDE.md §8 the
marker is now omitted entirely rather than left empty.
