# PR #56 review — fix(system): wifi_status reports true joined network + signal strength

2026-07-03, mode: fix

Copilot posted two inline comments, both aspects of the same issue.

(internal/engine/builtins_system.go) `renderWifiStatus` collapsed two distinct
states into the same "Not currently joined to a Wi-Fi network." output: a genuine
not-joined state AND an "unknown" state (system_profiler probe failed, output
unparseable, or our interface absent from the output). Reporting the unknown case
as "not joined" is a false connectivity claim — the exact false-negative this PR
set out to eliminate.

**fixed**
Replaced `parseCurrentWifiNetwork`'s `(wifiNetwork, bool)` return with a three-way
`wifiLookup` enum (`wifiJoined` / `wifiNotJoined` / `wifiUnknown`). Only a profiler
result that actually contains the resolved Wi-Fi interface can yield "Not currently
joined"; empty bytes (probe failed), unparseable JSON, or an interface-absent
result now render as "Unable to determine the current Wi-Fi network (system_profiler
data unavailable)" while still surfacing the authoritative radio-power line.
(f18b5e3)

---

(internal/engine/builtins_system_test.go) `TestRenderWifiStatus_ProfilerUnavailable`
asserted the output contains "Not currently joined" when system_profiler is
unavailable; it should assert the explicit unknown/"unable to determine" message
instead, and a separate genuine not-joined test (parseable JSON, interface present,
SSID empty) should exist.

**fixed**
Updated `_ProfilerUnavailable` to assert the "Unable to determine" message, that it
is NOT reported as not-joined, and that radio power is still surfaced. Added
`TestRenderWifiStatus_ProfilerUnparseable` and `TestRenderWifiStatus_InterfaceAbsent`
(both expect the unknown message). Tightened `TestRenderWifiStatus_NotConnected`
(the genuine not-joined case — parseable JSON with en0 present but SSID empty) to
also assert it is NOT reported as unknown. (f18b5e3)
