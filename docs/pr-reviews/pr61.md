## Comments and resolutions

### 1. `renderThermalState` could emit no verdict (builtins_diagnostics.go:313) — FIXED
Copilot noted that when `pmset -g therm` output matched neither `CPU_Speed_Limit`
nor the exact "No thermal warning level" wording (or if `CPU_Speed_Limit` failed
to parse), the function fell through to just the header + raw output — violating
its own doc comment ("leads with a plain-language verdict").

Fix: restructured so the function always resolves to exactly one `verdict` string
before appending the raw output — parsed limit (throttled / full-speed) → the
"no warning recorded" phrasing → an explicit "No explicit throttling indicator
was reported; see the raw pmset output below." fallback. Added a regression case
(`unrecognized wording still gets a verdict`) to `TestRenderThermalState`.

### 2 & 3. Hostile input used verbatim in subtest names (builtins_diagnostics_test.go:69, :86) — FIXED
The hostile-value tables include a newline and a NUL; using the raw value as the
subtest name (`t.Run("reject_process/"+h, …)`) produced unreadable names that can
interfere with test-output parsing.

Fix: both the process and subsystem rejection loops now name their subtests
`strconv.Quote(h)`, which escapes control characters into a stable, readable
form. The assertion still checks the original raw value.

### 4. `docs/TESTS.md` insertion broke the markdown table (docs/TESTS.md:22) — FIXED
This was the most important one. The V4 test description had been inserted into
the single-line `internal/engine` table cell **with raw newlines**. GitHub-flavored
markdown table cells cannot span raw newlines, so the insertion split the row
across physical lines, malforming that row and the alignment of the rows after it.

Fix: collapsed the addition back onto the one physical line of the `internal/engine`
cell (newlines → spaces). Verified the table is intact — rows for
`internal/registry`/`policy`/`engine`/`transaction`/`server` all begin with `|`
again, and the `## Security gate` section resumes cleanly after the table.
