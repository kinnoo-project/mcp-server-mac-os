# PR #16 review — Mvp2/impl12 (network diagnostics capability)

2026-06-20, mode: fix (addressing Copilot review comments)

(internal/engine/builtins_network.go) `ping_host` tries to bound runtime using
`ping -t <deadline>`, but Copilot reports that on macOS `-t` sets the IP TTL
rather than a timeout, which could produce false negatives for distant public
hosts and still not reliably prevent hangs. Suggests bounding with a context
timeout.

**fixed**
`ping_host` now bounds the whole probe with `context.WithTimeout(ctx, (count+5)s)`
and relies on ping's own `-c` (count) and `-W 2000` (per-reply wait, ms) for the
normal-case bound and the statistics summary; the `-t` flag is gone. When the
backstop fires (and the caller didn't cancel), it reports the timeout as data
("did not respond within …") rather than ping's signal-killed output.

Note on the premise: Copilot's claim that `-t` is the IP TTL is **incorrect for
our supported floor** (macOS Ventura+). `man ping` on Darwin documents
`-t timeout` in seconds, and `ping -c 2 -t 3 8.8.8.8` reaches the host fine
(reply ttl=116) — so there was no public-host false negative. The context-timeout
design is nonetheless better (it bounds a slow name resolution, which no ping flag
covers, and ties cancellation to the request), so it was adopted regardless.
Verified live: the reachable path returns a clean summary; an unreachable TEST-NET
host (192.0.2.1) returns "NOT reachable" via ping's own termination with no hang.

---

(internal/engine/builtins_network.go) `scan_lan`'s sweep uses `ping -t 1` with a
comment implying a 1s per-host timeout, but `-t` is not a per-probe wait. Use a
per-probe `context.WithTimeout` to enforce the 1s cap as intended.

**fixed**
`sweepSubnet` now wraps each probe in `context.WithTimeout(ctx, time.Second)` and
runs `ping -c 1 -W 1000` under it, so a non-responding host can't stall a worker.
The outer 20s sweep context still bounds the whole operation, and cancellation
still propagates. (Same `-t`-semantics correction as above applies, but the
per-probe context deadline is clearer and unambiguous either way.)
