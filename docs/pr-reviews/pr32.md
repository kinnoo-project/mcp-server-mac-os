(internal/evals/runner.go) applySetup's doc comment said the scratch dir is
created under `/tmp/...`, but the code uses `os.TempDir()`, which honors `$TMPDIR`
and is typically `/var/folders/…` on macOS. The mismatch would confuse anyone
debugging fixture paths.

**fixed**
Reworded the applySetup comment to describe `os.TempDir()`/`$TMPDIR` behavior.

(internal/evals/runner.go) applySetup created the scratch directory before
creating fixture files, but on any later error returned without removing the
partially-created tree — leaving residue on disk despite the harness being
self-cleaning.

**fixed**
applySetup now uses a named return + defer to `os.RemoveAll` the scratch tree and
return `""` on any post-creation error. Strengthened
TestApplySetup_CreatesAndConfines to assert the escaping-file case leaves nothing
behind.
