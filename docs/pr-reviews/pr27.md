# PR #27 review — feat(photos): add application-photos capability domain

2026-06-22, mode: fix

Addressed three Copilot review comments. Fix commit: `cd56af0`.

---

(internal/engine/builtins_photos_export.go) When export_photo fails (runOsascript
transport error or non-zero exit) or when Photos reports success but writes no
files, the code only calls os.Remove(outDir). os.Remove won't remove a non-empty
directory, and the early-return on `err != nil` doesn't clean up at all, so failed
exports can leave temp directories/files behind.

**fixed**
Every failure path after the temp directory is created now calls
`os.RemoveAll(outDir)` instead of `os.Remove`: the transport-error path and the
exportedFiles read-error path (which previously didn't clean up at all) now remove
the directory, and the non-zero-exit / zero-files paths use RemoveAll so a partial
export that left the directory non-empty is still cleaned up. A partial export can
write files and then fail, which is exactly the case os.Remove could not handle.

---

(internal/engine/builtins_photos.go) list_albums builds tab-delimited rows but
doesn't sanitize album names. If an album name contains a tab/newline, it will
corrupt the row contract and either misparse or be skipped. Other AppleScript row
emitters in this repo run text fields through `my _clean(my _str(...))` (see e.g.
builtins_notes.go) to preserve the one-row-per-line format.

**fixed**
`listAlbumsScript` now prepends `asDateHelpers` and emits the album name as
`my _clean(my _str(name of a))`, flattening any tab/return/linefeed to spaces and
coercing a missing name to "", consistent with the `_row` helper and the other
osascript-backed list operations.

---

(internal/engine/builtins_photos.go) list_photo_folders emits tab-delimited rows
but doesn't sanitize folder names. A folder name containing a tab/newline can break
the row format and cause items to be misrendered or dropped. Using `asDateHelpers`'
`_str` + `_clean` here keeps output parsing robust, consistent with other
osascript-backed list operations.

**fixed**
`photoFoldersScript` now prepends `asDateHelpers` and emits the folder name as
`my _clean(my _str(name of f))`, same treatment as list_albums above.

---

**Note on tests:** all three fixes live on the AppleScript side (the `_clean`/`_str`
sanitization) or behind a live `osascript` call (the export cleanup runs only after
`runOsascript` returns), so they sit on the manual-smoke side of this domain's
testing boundary — there is no in-Go seam to exercise them without launching
osascript, mirroring how the rest of the Photos write paths are covered (see the
photos safety note in docs/TESTS.md). `go build ./... && go vet ./... && gofmt -l
. && go test ./...` all pass.
