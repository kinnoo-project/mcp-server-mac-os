# PR #36 review — feat(filesystem): write_file + append_to_file (U1)

2026-07-02, mode: fix (Copilot review)

(internal/engine/mutate_filesystem.go) append_to_file enforced the 8 MiB
target cap via os.Stat but then read the file with os.ReadFile without
re-checking — a TOCTOU window in which a growing file could push an oversize
payload into the undo token store.

**fixed**
The cap is re-checked on `len(prior)` — the bytes actually read, which are
what the undo store would hold. The stat check stays as the cheap fast-path
error.

---

(internal/engine/mutate_filesystem.go) tee echoes what it writes, so execute
echoed the written content back and — worse — undo echoed the file's PRIOR
contents (up to the 32 KB compaction window) to the client: a leak of data the
client never read through any approved operation.

**fixed**
`engine.Command` gains `DiscardStdout`; `RunCommand` drops the child's stdout
(stderr/exit code still surface) when set. All three tee commands set it. Plan
tests assert the flag on forward and inverse, and
`TestRunCommand_DiscardStdoutSuppressesEcho` proves end to end that a
sensitive stdin payload is written to disk but never echoed into the tool
result. Design note updated (its earlier "echo is harmless" claim was wrong).
