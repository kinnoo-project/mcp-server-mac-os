# PR #47 — screenshot: capture_region + capture_window (U12)

Copilot reviewed 12/12 changed files and left **3 inline comments** (state:
COMMENTED). All three were reasonable and are addressed in commit `4d68282` (on
top of the implementation `5da2b58`). None were bugs in the shipped happy path;
two were correctness/UX refinements and one was a test-coverage gap.

## Comments and resolutions

### 1. `positiveDimension` hard-codes "pixel", but a region is in points
`builtins_screenshot_region.go` reused `positiveDimension` (from the window
mutators) for `capture_region`'s width/height, but that helper's error messages
and comment said "pixel", while the region manifest/docs describe x/y/width/height
in **screen points**. Inconsistent user-facing vocabulary.

**Fix:** `positiveDimension` now takes a caller-supplied `unit` word — `"pixel"`
for the window mutators (`resize_window`), `"point"` for `capture_region`. The
error text now matches each capability's own manifest wording. `TestPositiveDimension`
gained an assertion that the `capture_region` path produces a "point"-worded error.

### 2. `capture_window` probed geometry before validating `output_path`
`capture_window` called `probeWindowGeometry` (a permission-gated System Events
call) *before* `runCapture` validated `output_path`. For an obviously-invalid
dash-leading path, that could fire an Automation/Accessibility prompt — or surface
a `windowScriptError` — ahead of the simple input-validation error.

**Fix:** the window-bounds read is now deferred behind a `regionFn` callback that
`runCapture` invokes only **after** the cheap, non-prompting validation (format,
`output_path` dash-guard, no-overwrite check) passes. An invalid request now fails
fast with no System Events call. `capture_region` was moved to the same `regionFn`
shape (its callback just returns the already-validated rectangle), so the spine has
one uniform contract.

### 3. No test for `capture_window` rejecting a dash-leading `output_path`
Given the fail-fast ordering above matters for avoiding spurious prompts, a
regression here should be caught.

**Fix:** added `TestCaptureWindow_RejectsDashLeadingOutputPathFast`, which feeds a
dash-leading `output_path` and asserts the failure is the **path-guard** message
("must not begin with") — a message only produced if path validation ran *before*
the window probe. So the test pins the ordering, not merely the rejection.
