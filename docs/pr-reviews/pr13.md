# PR #13 review — support for opening files

2026-06-19, mode: fix

(internal/registry/manifests/application.json) `open_file` defines the application
parameter as `app`, but the mutator calls `validateAppName`, which reads `name` —
so staging would always fail with "'name' is required". Copilot suggested renaming
`app` → `name` to match open/focus/quit.

**fixed**
Already resolved on this branch in commit 8673385 — but via a different approach
than the suggested rename, because `app` is the better fit here. The mutator now
reads the `app` parameter through a new field-aware validator
(`validateAppNameValue`), and `app` is *optional*: omitting it opens the file in
the system default handler (`open -- <file>`), which a rename to the required-style
`name` convention would have foreclosed. Keeping `app` also reads more clearly for
"open a file *with* an app" than the bare `name` the launch/quit verbs use. The
leading-dash and control-character guards are unchanged. Regression test
`TestStageOpenFile_ReadsAppParam` pins that the `app` param is the one read (a
flag-like app fails with the leading-dash message, which only happens if the value
was actually read).

---

(internal/engine/mutate_apps_test.go) The `open_file` test cases pass `app`, but
validation read `name`, so they failed early with "'name' is required" instead of
exercising the intended paths.

**fixed**
Resolved alongside the above. Tests now pass `app` and exercise the real paths: a
*missing* app is treated as valid (the default-app path, covered by
`TestStageOpenFile_DefaultApp`), and `TestStageOpenFile_ReadsAppParam` asserts the
named branch genuinely reads and validates `app`.

---

(internal/engine/appdocs.go) `parseDocTypes` reported `declaredAny=true` whenever
`CFBundleDocumentTypes` existed, even if no entry contained any
`CFBundleTypeExtensions` or `LSItemContentTypes`. An app that names zero types has
effectively made no claim, so `assessFileSupport` should treat it as
`supportUncertain`, not a confident `supportUnsupported` mismatch.

**fixed**
`declaredAny` is now `len(exts) > 0 || len(utis) > 0` — true only when at least one
extension or UTI was actually extracted. Added `TestParseDocTypes_EmptyEntriesAreNoClaim`
covering CFBundleDocumentTypes entries that declare neither extensions nor UTIs.

## Also in this pass (user smoke-test feedback, not a Copilot comment)

The staged preview read too generically before confirming. Reworked
`composeOpenFilePreview` (and the default-app preview) to lead with a concrete
sentence and a call to action — e.g. `Open file ~/Downloads/Leah.png with
"Preview". It will be launched; undo will quit it again. Proceed?` — instead of the
prior `Open <path> in "<app>". …`. Warnings (unsupported / uncertain) still lead on
their own line so risk is seen first. Updated `TestComposeOpenFilePreview` and the
architecture/issue docs to match.
