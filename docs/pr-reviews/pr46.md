# PR #46 — feat(application): window management (U11)

Base: `build` · Branch: `feat/window-management` · Copilot review: **COMMENTED** (9 inline)

## Summary

Adds window management to the existing `application` domain (no new MCP tool):
`list_windows` (read-only) plus `move_window` / `resize_window` /
`minimize_window` (reversible / low / auto_commit, each with an undo built from
the window's prior state). All four drive windows through System Events / the
Accessibility API via the hardened `osascript` seam. First unit to require TWO
TCC grants at once (Accessibility + Automation), distinguished by the new
`windowScriptError`.

## Copilot review outcome

Copilot generated **9 inline comments** (plus the standard overview). No approval
gate blocked. The 9 clustered into four themes — all valid, all addressed in
`52ebbd8`. None was a functional defect in the shipped happy path; the most
substantive (title newline) was a real output-corruption edge case.

### Theme A — stale `_windows.go` filename references in header comments (5 comments, FIXED)

**Files:** `mutate_windowing.go:4`, `:20`; `builtins_windowing.go:2`, `:11`

The file header doc comments still referenced the original `mutate_windows.go` /
`builtins_windows.go` names from before the files were renamed. (They were
renamed precisely because a `_windows.go` suffix is an implicit `GOOS=windows`
build constraint that silently excludes the file on darwin — see the design
note.) Copilot rightly flagged that keeping these references accurate matters
*more* than usual here given that hazard.

**Fix:** replaced every `mutate_windows.go` → `mutate_windowing.go` and
`builtins_windows.go` → `builtins_windowing.go` in the header comments.

### Theme B — `list_windows` title not newline-flattened (1 comment, FIXED)

**File:** `builtins_windowing.go:58`

> `listWindowsScript` treats the window title as arbitrary user text, but it
> doesn't sanitize embedded `return`/`linefeed`. If a title contains a newline,
> `asRows()` will split the output mid-row and `renderWindowList` will mis-parse
> (other AppleScript row emitters in this repo call `_clean`). Consider
> flattening `{tab, return, linefeed}` in `wtitle`.

**Assessment:** Correct and the most substantive comment. The field delimiter
(`\x1f`, `windowFieldSep`) already made *tabs* inside a title harmless, but rows
are split on linefeed, so a title containing a newline (rare but possible — some
apps put multi-line strings in a window's accessibility title) would split one
window across two rows and mis-parse. This mirrors exactly why the
Calendar/Reminders emitters use `_clean`.

**Fix:** `listWindowsScript` now flattens `{tab, return, linefeed}` in the title
to single spaces (via `text item delimiters`, the same technique as `_clean`)
before emitting the row. Updated the `windowFieldSep` doc comment to spell out
the field-vs-row split distinction. (The flatten runs in AppleScript, so it is
not directly unit-testable in-process — consistent with the other `_clean`
call sites; `renderWindowList`'s existing field-count guard remains the Go-side
backstop.)

### Theme C — manifest summaries named only Accessibility, not both grants (3 comments, FIXED)

**File:** `internal/registry/manifests/application.json:190`, `:231`, `:272`
(move / resize / minimize)

The three mutator summaries said the op "needs Accessibility access", but window
control needs BOTH Accessibility and Automation (to control System Events) — the
exact two-way split `windowScriptError` maps. A user hitting a `-1743` Automation
denial would have been confused by a summary that named only Accessibility.

**Fix:** all three summaries now read "on first use macOS asks for BOTH
Accessibility and Automation access", matching the error mapping.
(`list_windows`'s summary already named both.)

### Theme D — test comment overstated coverage (1 comment, FIXED)

**File:** `mutate_windowing_test.go:155`

`TestWindowMutators_HostileAppLandsAsData` claimed to "exercise every window
script" but only asserted `planMoveWindow`.

**Fix:** the test now builds the forward for move, resize, AND minimize and
asserts each places the hostile app name immediately after the `--` terminator —
matching the comment, and genuinely covering all three scripts.
