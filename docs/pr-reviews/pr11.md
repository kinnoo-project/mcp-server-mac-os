# PR #11 review — Mvp2/impl8

2026-06-19, mode: fix (addressing Copilot review comments)

(internal/engine/builtins_apps.go) listApps() hard-codes the operation name as
`list_applications` in its mdfind-failure error, but the same helper also serves
`search_applications`, so a failure during a search would be misreported.

**fixed**
listApps now takes the calling operation name as a parameter and uses it in the
error; runListApplications passes "list_applications" and runSearchApplications
passes "search_applications".

---

(internal/server/menu.go) executionLane() advertised auto-commit reversible
operations as "reversible via undo", but some capabilities (e.g.
open_application when the app is already running) intentionally omit an inverse,
so no undo token is returned — the wording overstated the guarantee to the model.

**fixed**
The auto-commit lane phrase is now "runs immediately; may return an undo token",
with a doc comment explaining why it hedges. Updated the matching wording in
README.md and docs/issues/note-auto-commit-lane.md.

---

(.claude/skills/wrap-up.md) Typo: "sessino" → "session".

**status**: open — the harness auto-mode classifier blocks edits to agent-config
files (.claude/skills/*), so this one was not applied. It is a trivial one-word
typo fix the user can make by hand (or re-run with that file approved).

---

(internal/engine/mutate_messages.go) Attachment validation only rejected
directories, but attachments are documented as regular files; non-regular objects
(device nodes, sockets, FIFOs) could be staged and would then fail opaquely in
AppleScript at commit time.

**fixed**
Validation now requires info.Mode().IsRegular() instead of merely "not a
directory". Added TestStageSendMessage_RejectsNonRegularAttachment (creates a
FIFO and asserts rejection).

---

(internal/server/tools.go) autoCommitMutation() discarded the staged
plan.Preview and returned only the command output plus the capability name. For
open_settings / open_application the command output is usually empty, so the
caller got "Done: <name>" with no description of what happened.

**fixed**
autoCommitMutation now leads with the preview via composeAutoCommitDescription,
which joins the preview with command output (dropping either when empty so there
are no dangling blank lines). The redundant "This cannot be undone." was removed
from open_application's already-running preview since the response suffix now owns
the reversibility statement.

---

(internal/engine/mutate_apps.go) stageOpenApplication ran a System Events
AppleScript probe to decide whether to offer an undo. On first use that probe can
trigger an Automation permission prompt and block the request — bad for a
low-friction auto-commit operation.

**fixed**
The running check is now appAlreadyRunning, which parses `lsappinfo list` (Launch
Services — no Automation grant required) instead of a System Events probe. It
biases toward "running" (no undo) on any uncertainty so undo can never quit an
app the user already had open. Matching (lsappinfoListsApp) is case-insensitive
on both the display name and the .app bundle basename, mirroring how `open -a`
resolves a name. Added TestLsappinfoListsApp covering exact/case-insensitive/
bundle-name/space/non-running/partial/empty inputs.
