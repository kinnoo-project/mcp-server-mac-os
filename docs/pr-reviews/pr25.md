# PR #25 review — build -> main

2026-06-22, mode: fix

(internal/engine/mutate_apps.go) normalizeWebsiteURL/validateWebURL currently
allow URLs with userinfo (e.g. `https://user:pass@host` or
`https://trusted.com@evil.com`). These are commonly used for deceptive/phishing-
style URLs and can also leak credentials. Since this tool is intended for opening
ordinary websites, consider rejecting any URL containing userinfo. (Copilot)

**fixed**
`validateWebURL` now returns an error whenever `url.URL.User` is set (commit
c0af907), so both `https://user:pass@host` and `https://trusted.com@evil.com` are
refused. The second form is the classic phishing disguise — `trusted.com` is only
userinfo and the browser navigates to the host after the `@` (`evil.com`) — and the
first would hand credentials to `open`. An ordinary website never needs userinfo.
Added regression cases to `TestNormalizeWebsiteURL` (both forms plus a bare
`user@example.com`, which has no scheme and resolves to userinfo@host after the
https default); updated `docs/issues/note-open-website-design.md` and `docs/TESTS.md`.
