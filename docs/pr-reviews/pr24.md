# PR #24 review — feat(application): add open_website to open a web address in a browser

2026-06-22, mode: fix

(internal/engine/mutate_apps.go) normalizeWebsiteURL currently rejects bare
host:port inputs that lack a dot (e.g. "localhost:8080") because url.Parse treats
them as Scheme/Opaque and the code treats that as a non-http(s) scheme. This
contradicts the nearby comment about allowing host:port bare domains, and prevents
common dev URLs from working. It also treats malformed "http:example.com" /
"https:example.com" as a bare domain and rewrites them into an incorrect URL.
Consider allowing Scheme/Opaque when Opaque is an all-digit port (host:port),
while still rejecting known non-web schemes (tel/mailto/file/...). Also explicitly
reject http/https when they appear without "://". (Copilot)

**fixed**
Reworked the no-`://` branch of `normalizeWebsiteURL` (commit dec50f4). The old
"scheme contains a dot ⇒ host:port" heuristic was the root cause: `localhost:8080`
has no dot in its host, so it was misclassified as a non-web scheme and rejected.
New logic for a no-`://` value that `url.Parse` reports a scheme for:
- http/https without `//` (`http:example.com`) → rejected as malformed instead of
  being silently rewritten to `https://http:example.com`.
- a known non-web scheme (`tel`, `sms`, `mailto`, `file`, `ftp`, `ftps`,
  `javascript`, `data`, `smb`, `afp`, `vnc`, `ssh`, `facetime`, …) → rejected with
  the "only http and https" message (checked before the port test, so `tel:911`'s
  all-digit opaque doesn't slip through as a host:port).
- an all-digit opaque (the port) → accepted as a host:port and defaulted to https,
  so `localhost:8080`, `example.com:8080`, and `127.0.0.1:3000` now work.
- anything else (`myapp:foo`) → rejected.
The security guarantee is unchanged: whatever is returned is an http/https URL
with a host, so `open` is only ever handed a web address. Extracted two helpers
(`validateWebURL`, `isAllDigits`) to keep the function readable. Extended
`TestNormalizeWebsiteURL` with the three host:port acceptances and the new
rejections (`sms:911`, `http:example.com`, `https:example.com`, `myapp:foo`);
updated `docs/issues/note-open-website-design.md` and `docs/TESTS.md`.
