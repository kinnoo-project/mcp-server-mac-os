**bug**
The new server panicked on startup with `mcp.AddTool: tool "list_capabilities": input schema: ... tag must not begin with 'WORD='`. The `jsonschema` struct tags on the engine tools' argument structs (`QueryArgs`, `ListCapabilitiesArgs`, `DescribeCapabilityArgs`) used the form `jsonschema:"required,description=..."`. The SDK's schema library (`github.com/google/jsonschema-go` v0.4.2) treats the **entire** tag value as the property description and explicitly rejects any value beginning with `WORD=` (a run of non-whitespace characters followed by `=`), so both `required,description=...` and `description=...` were invalid. The unit tests did not catch this because they call the handler functions directly and never exercise `mcp.AddTool`'s schema generation — the panic only appeared when the real binary booted and registered its tools. (Surfaced during Slice D; the buggy tag style originated in the Slice B/Slice D server code.)

**fixed**
Rewrote the tags as plain description text (the whole tag value is the description in this library) and relied on the library's convention that a field is required unless its `json` tag carries `omitempty` — so `capability` remains required while `params`/`category` are optional, with no `required`/`description=` syntax needed. Added a regression guard, `TestRegister`, which builds a real `mcp.Server` and calls `Register`, running `AddTool`'s schema generation for every tool and failing the test on any invalid tag. This turns a runtime startup panic into an ordinary unit-test failure.
