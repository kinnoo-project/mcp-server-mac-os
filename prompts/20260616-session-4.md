⏺ Done. send_message can now send file attachments over iMessage.

  What I changed

  Behavior: send_message gained an optional attachments parameter — one or more
  file paths (an image, PDF, etc.). You can send a file with text, or a file
  with no text at all. Your original request — "Send Leah.png in ~/Downloads as 
  an iMessage to Wei Zuo" — now works: the ~/Downloads/Leah.png path is
  tilde-expanded, checked to exist, and sent as an attachment to the contact
  resolved from "Wei Zuo."

  How it's wired (matching the existing send_mail pattern):
  - The recipient, text, and attachment paths cross into AppleScript only as
  data bound to on run argv behind the -- end-of-options terminator — the script
  body stays a fixed reviewed constant, so there's no injection surface.
  - The flat argument list is [handle, text, attachmentCount, paths...]. The
  explicit count is what lets the variable-length path list share one argv
  without a delimiter that a path might contain.
  - The AppleScript sends attachments first, then any text (mirroring how the
  Messages UI stacks an image above its caption). Each is a separate send —
  AppleScript has no single image-with-caption send.
  - text became optional in the manifest, and "text OR attachments — not
  nothing" is enforced in Go, because the engine's required-field check runs
  before the stage function, so a conditional rule can't live in the manifest.
  - Each attachment is os.Stat-checked at stage time (must exist, must not be a
  directory) before the irreversible send is staged, and the confirmation
  preview names each file.

  Safety unchanged: it's still irreversible (nil inverse, no "unsend"), still
  goes through the stage → execute confirmation gate with the message shown
  verbatim.

  Verification: go build, go vet, and the full go test ./... all pass. New tests
  cover with-attachments, attachments-only (no text), and rejection of a
  missing file and a directory path — no test ever executes a send. Docs updated
  (README, TESTS.md, a new design note in docs/issues/), and committed as
  8f17164.

  Caveat worth flagging: as with the rest of the Messages send path, the exact
  osascript attachment incantation ((POSIX file path) as alias → send … to 
  targetBuddy) is macOS-version-sensitive and can't be unit-tested without
  sending a real message. It's worth a one-time manual smoke test — sending a
  small image to your own Apple ID — to confirm it works on your machine before
  relying on it.
