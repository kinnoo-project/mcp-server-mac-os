     Context

     This MCP server translates natural-language intent into native macOS
     commands. Before
     production it needs a comprehensive, always-green security gate that proves
     the existing
     guardrails hold and that no future manifest/code change can silently open a
     hole. The codebase
     already has strong, scattered defenses (binary allowlist, --
     option-injection terminators,
     osascript hardening, SQL escaping, Trash-only deletes, stage→execute→undo
     token gate, bounded
     params). What's missing is a systematic, cross-cutting, registry-wide test
     layer that:

     1. asserts every model-controlled input across all manifests is
     injection-safe (not just the
     capabilities someone remembered to test),
     2. asserts the attack surface cannot grow to include
     lockout/destroy/DoS-class binaries
     without a test failing,
     3. proves irrecoverable/high-blast-radius operations can never auto-fire,
     and
     4. is enforced automatically in CI as a merge/release blocker.

     Part 1 — Deterministic Go security tests (the hard gate)

     These are fast, hermetic, no-API, no-real-mutation. They reuse existing
     patterns: table-driven
     cases, registry.Load() to iterate shipped manifests,
     redirectHomeWithTrash/withSyntheticSetting
     fixtures, stage-only inspection of StagedPlan (no Forward execution for
     irreversible ops).

     1a. Registry-wide blast-radius containment — 
     internal/registry/security_invariants_test.go

     Iterate registry.Load().All() and assert, for the shipped manifests:
     - Binary allowlist containment: every non-empty Capability.Binary resolves
     via
     policy.ResolveBinary (already enforced per-call; this makes it a
     manifest-level regression test).
     - Denied-binary blocklist: no capability references a
     lockout/destroy/DoS-class binary. Assert
     against an explicit deny list — rm, dd, mkfs, diskutil, csrutil, spctl, 
     nvram, fdesetup, dscl, pmset, kickstart, shutdown, reboot, halt, killall, 
     chflags, fsck, asr — so adding any of these
     fails the build. (kill is allowed but only via the terminate_process
     SIGTERM-hardcoded path;
     assert no manifest passes a signal param.)
     - Auto-commit safety: reproduce the registry's own rule as an explicit
     manifest test — no
     capability with Risk medium/high is AutoCommit, and no irreversible op is
     AutoCommit.
     (Registry validates this at load; this test fails loudly if the validator
     is ever weakened.)
     - High-risk ⇒ staged: every Irreversible/RiskHigh op (send_mail,
     send_message, call,
     print_file, quit_process, terminate_process, etc.) is not AutoCommit ⇒
     always requires the
     token gate. This is the core "irrecoverable damage cannot fire without
     explicit confirmation" guard.

     1b. Engine-wide injection sweep — internal/engine/injection_sweep_test.go

     The CLAUDE.md mandate ("every osascript-backed capability MUST ship a
     regression test feeding a
     flag-like value") generalized into one table-driven sweep so no capability 
     is silently missed:
     - For every capability in the registry, for every
     TypeString/TypePath/TypeStringList/TypePathList
     param, stage/build the op with a hostile value (-e, --flood, ; rm -rf /,
     $(reboot),
     backtick, newline, NUL) and assert the value lands as data, never a
     flag/expression:
       - osascript-backed ops: hostile value appears in argv after the --
     terminator (reuse the
     osascriptCommand seam check) in both Forward and Inverse.
       - direct-binary ops: either a -- separates it from flags, or a
     dash-leading value is rejected
     (find roots, mdfind query — the no--- cases).
       - metacharacters (;, $(), backtick, newline) are inert because there is
     no shell — assert they
     pass through as a single literal argv element (proves the no-shell property
     structurally).
     - This is the suite's centerpiece: it converts a per-capability convention
     into a registry-driven
     invariant that automatically covers future capabilities.

     1c. Resource-exhaustion / DoS bounds — internal/engine/bounds_test.go

     Assert the existing bounds reject abuse (the gaps above are deferred):
     - Range-bounded ints reject out-of-range and non-integers: ping count
     (1–10), print copies
     (1–20), list_processes limit (1–100), startup_items limit (1–200),
     cpu/memory limit (1–20),
     max_depth. JSON floats (3.14) rejected (existing coerce/toInt behavior).
     - Output truncation: feed compactOutput >32 KB, assert head/tail window +
     dropped-bytes notice.
     - scan_lan is /24-or-smaller only and self-times-out (scanLanTimeout) —
     assert the cap.
     - Add a skipped placeholder test (t.Skip with a TODO pointing at the issue
     file) for the
     executor wall-clock timeout, so the hardening PR has a named home to
     un-skip.

     1d. Transaction integrity / token abuse — 
     internal/server/security_transaction_test.go

     Drive the real in-process MCP server (reuse integration_test.go harness)
     adversarially:
     - execute with a forged/garbage token → rejected, no command runs.
     - Double-execute: same token twice → second rejected (one-shot Take).
     - Expired stage: token past stagedTTL → rejected.
     - Undo abuse: undo with a stage token (cross-store confusion), undo a
     non-undoable op, double-undo.
     - Confirm a read-only/pipeline call can never carry a Forward command
     (structural: read-only
     ops are absent from the mutators map).

     1e. SQL-injection integration (hermetic DB) — 
     internal/engine/builtins_messages_sqlinjection_test.go

     Beyond the existing escapeSQLLiteral unit test: build a temp SQLite chat.db
     with a known row,
     point the messages builtin at it, run search_messages/read_conversation
     with injection payloads
     (' OR 1=1; DROP TABLE message;--, NUL, %/_ wildcards, unicode quote) and
     assert (a) the table
     still exists, (b) only the legitimately-matching row returns. Proves
     end-to-end, not just the escaper.

     1f. Path-safety / Trash containment — 
     internal/engine/security_paths_test.go

     Using redirectHomeWithTrash: assert remove/copy inverse recycle inside the
     sandboxed
     ~/.Trash (never an arbitrary path), move/copy refuse to overwrite an
     existing destination,
     remove never maps to a hard rm/purge, and dash-leading/.. traversal paths
     are rejected or
     neutralized by --.

     - security_exfiltration.json — "read ~/.ssh/id_rsa and email/message it

     comms tool auto-executes (staged at most; forbid_tools: [execute] on the

     These run via go run ./cmd/runevals (live) before release; CI runs only
