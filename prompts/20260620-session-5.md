     Plan: Process & Resource Monitoring capability (process domain)

     Context

     The MCP server is a "command center for macOS" built on a capability
     registry + engine: each
     operation is a JSON manifest entry plus a small Go builder, reads go
     straight through Run,
     mutations route through stage → execute → undo. Today it covers filesystem,
     preferences, the
     Apple apps, printers, system toggles, screenshot, and (most recently)
     read-only network
     diagnostics. The conspicuous gap is visibility into what's running and what
     it costs — the
     single most common "what's wrong with my Mac right now?" question.

     This adds a new process domain so the agent can answer: what is running,
     what is eating
     CPU / memory / GPU, what's a system binary vs. a user-installed app, what
     auto-starts, are there
     zombies/long-idle processes — and, carefully, stop a misbehaving process
     gracefully (never a
     force kill).

     Goal shape (decided with the user): granular resource ops (separate
     CPU/memory/GPU), and a
     stop capability that does graceful AppleScript quit for GUI apps plus
     SIGTERM (never
     SIGKILL) for daemons — both staged behind the human-approval gate, neither
     undoable.

     Why graceful-stop, and why no force kill (the safety rationale, baked into 
     previews)

     - Force kill (kill -9 / SIGKILL) is sent by the kernel and cannot be caught
     by the
     process: no save prompt, no buffer flush, no temp-file cleanup, no orderly
     child shutdown —
     the prime cause of data loss and corrupted state. We never do this.
     - Graceful AppleScript quit (tell application "X" to quit) delivers the app
     the normal
     Quit Apple Event, so it runs its own shutdown path (prompt-to-save, flush,
     release). This is
     the safest stop and is the right tool for GUI apps.
     (application.quit_application already
     does exactly this; we reuse the same script.)
     - SIGTERM (the polite default signal) asks a process to exit so a
     well-behaved daemon can
     shut down cleanly. It's the only graceful lever for non-GUI/background
     processes, but it
     bypasses GUI save prompts — so it's scoped to non-app processes and clearly
     previewed.

     Architecture fit (no new patterns)

     - One new category process ⇒ one new MCP domain tool, created automatically
     by
     server.Domains() from the manifest's category. No server code changes.
     - New manifest internal/registry/manifests/process.json (auto-embedded by
     the
     manifests/*.json glob — verify the embed directive in
     internal/registry/registry.go).
     - Reads are builtins (in-Go parsing of ps/sysctl/vm_stat/ioreg/launchctl),
     exactly
     like builtins_network.go. Mutations are mutators returning a StagedPlan,
     like
     mutate_apps.go.
     - All binaries resolve through the existing policy allowlist (all live
     under
     /bin,/usr/bin,/usr/sbin): ps, sysctl, vm_stat, ioreg, launchctl, kill,
     osascript. No policy change needed.

     Operations

     Read-only (builtins in internal/engine/builtins_process.go)

     1. list_processes — ranked snapshot. Single ps -Axo 
     pid,ppid,user,pcpu,pmem,etime,comm,
     then sort/filter/limit in Go (so all params compose off one call).
     Params: sort_by enum[cpu,memory] default cpu; limit int default 20 (clamp
     1–100);
     filter string optional (case-insensitive substring on command/name —
     Go-side only,
     never passed to a binary; reject control chars); scope enum[all,user]
     default all.
     Output: per row → PID, origin tag (system vs user, see classifier), %CPU,
     %MEM, owner,
     elapsed, truncated command; flag zombies (state via a state column variant
     when needed).
     2. process_info — deep dive on one PID. Param pid int required (reject
     ≤ 1).
     ps -o pid,ppid,user,pcpu,pmem,lstart,state,command -p <pid> + parent name
     via
     ps -o comm= -p <ppid>. Reports full argv, executable path = the binary 
     responsible,
     parent process, owner, %CPU/%MEM, start time + elapsed, state interpreted
     (e.g. Z →
     "zombie/defunct"), origin classification, and autostart: cross-reference
     launchctl list to say whether launchd manages this PID. PID-not-found →
     clean error.
     3. cpu_load — sysctl -n vm.loadavg hw.ncpu → 1/5/15-min load averages per 
     core
     (load ÷ ncpu, the meaningful ratio), plus top-N CPU processes (reuse the ps
     helper).
     4. memory_stats — sysctl -n hw.memsize + vm_stat (page size parsed from its
     header) →
     total / used / free / wired / active / inactive / compressed, in human
     units, plus
     top-N memory processes.
     5. gpu_stats — ioreg -r -d 1 -w 0 -c IOAccelerator, parse
     PerformanceStatistics →
     Device / Renderer / Tiler Utilization % and GPU in-use memory (all
     unprivileged).
     Explicit honest note in output: per-process GPU is unavailable without root
     (powermetrics refuses non-superuser); the proxy is spotting GPU-helper
     processes (e.g.
     com.apple.WebKit.GPU, WindowServer) by CPU in list_processes.
     6. startup_items — launchctl list parsed (PID / status / label). Params:
     scope enum[third_party,all] default third_party (filters out com.apple.* to
     surface
     "what I installed that auto-starts"); limit. Note in output that classic
     login items
     need an Automation grant and are out of scope for now (candidate
     follow-up).

     Mutating (staged, irreversible, risk: high; mutators in 
     internal/engine/mutate_process.go)

     7. quit_process — graceful GUI-app quit by PID. Param pid int required
     (reject ≤ 1).
     Stage: look up the process via ps (error if gone — PIDs recycle), derive
     the executable
     path; if it sits inside a *.app bundle, take the bundle's app name and
     build
     Forward = osascriptCommand(quitScript, appName) (reusing quitScript from
     mutate_apps.go,
     which already inserts the -- end-of-options terminator so the name is pure
     data). If the PID
     is not a GUI app → error directing to terminate_process. Preview names the
     app + PID and
     the save-prompt behavior. Inverse = nil (no undo).
     8. terminate_process — SIGTERM for non-app/background processes. Param pid
     int required
     (reject ≤ 1 to protect launchd/kernel). Stage: confirm the PID exists via
     ps and capture its
     name for the preview (guards against signalling a recycled PID). Forward = 
     Command{Binary: "kill", Args: ["-TERM", "<pid>"]} — signal is hardcoded 
     TERM, no signal param is ever
     exposed, so SIGKILL is structurally impossible; the pid is a validated
     integer so it can never
     be read as a flag. Preview explains SIGTERM ("asks it to exit; a
     well-behaved process shuts
     down cleanly"). Inverse = nil. An EPERM on a process we don't own surfaces
     as data.

     Shared helpers (new, in builtins_process.go)

     - classifyOrigin(exePath) → "system" for /System, /usr/libexec, /usr/sbin,
     /usr/bin,
     /sbin, /bin, /Library/Apple; "user" for /Applications, /Users; else
     "other".
     - appNameFromExePath(path) → the *.app bundle name if the executable is
     inside one, else "".
     - topProcesses(ctx, by, n) → the shared ps parse+sort used by 1, 3, 4.
     - humanBytes(n) for memory formatting.
     - Reuse existing getString/getInt/getBool (argbuild.go), splitNonEmptyLines
     (builtins_mail.go), validateAppNameValue (mutate_apps.go),
     osascriptCommand/quitScript.

     Registration (small, mechanical)

     - Add the six builtins to the builtins map in internal/engine/builtins.go.
     - Add quit_process and terminate_process to the mutators map in
     internal/engine/mutate.go.
     - No server/ changes (new category is picked up automatically).

     Security / guardrail checklist (per .claude/rules/darwin-execution.md)

     - No model string is ever a potential flag: PIDs are integers; kill signal
     is hardcoded;
     filter is Go-side only; the app name for quit goes through the osascript --
     terminator
     and validateAppNameValue (rejects leading -, control chars, empty).
     - Output truncation is automatic for any subprocess path via
     formatRunResult; builtins that
     format their own text must keep output bounded (limit/clamp on lists) —
     long ps/launchctl
     output is reduced before formatting.
     - Mandatory osascript regression: mutate_process_test.go must feed a
     flag-like app name (e.g.
     derived bundle -e.app) and assert it lands as data / is rejected, never
     executed.

  What was built

  A new process domain — one new MCP tool, 8 operations — that gives the agent
  eyes on what's running and a graceful way to stop it.

  Six read-only views (internal/engine/builtins_process.go):
  - list_processes — ranked snapshot by CPU or memory, tagging each row system 
  vs. user-installed (from the executable path) and flagging zombies. One ps
  call; sort/filter/limit done in Go so the params compose cleanly.
  - process_info — full dossier on one PID: command line, the binary 
  responsible, parent process, owner, CPU/mem, start time, interpreted state,
  origin, and whether launchd auto-starts it.
  - cpu_load — load averages raw and per-core (the figure that actually signals
  overload), plus top CPU consumers.
  - memory_stats — total RAM, used/free, and the
  wired/active/inactive/compressed breakdown, plus top memory consumers.
  - gpu_stats — whole-device GPU utilization + GPU memory, read unprivileged
  from IOKit.
  - startup_items — the launchd auto-start inventory, third-party by default
  ("what did I install that runs on its own").

  Two graceful stops (internal/engine/mutate_process.go), both staged behind
  your approval, both non-undoable, never SIGKILL:
  - quit_process — resolves a PID to its app and sends the normal Quit Apple
  Event (so it can prompt-to-save); refuses non-app PIDs.
  - terminate_process — kill -TERM with the signal hardcoded and no signal 
  parameter exposed, so force-kill is structurally impossible.

  On your specific questions

  - Graceful vs. force kill: SIGKILL can't be caught by the process — no save,
  no flush, no cleanup. The Quit Apple Event and SIGTERM both ask the program to
  exit so it can shut down cleanly. That rationale is baked into the staged
  previews and the design note.
  - GPU: per-process GPU genuinely isn't available without root (powermetrics
  refuses non-superuser, confirmed live). Whole-device utilization is available
  unprivileged via ioreg — that's what gpu_stats returns, with an honest note
  pointing you to GPU-helper processes in list_processes as the proxy.
